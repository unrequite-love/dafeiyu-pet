# 大肥鱼桌宠 —— 设计思路文档

> 用途：总结本项目在产品、工程、体验三个层面的设计决策与理由，
> 供生成同类项目时借鉴。配套[架构文档](ARCHITECTURE.md)看结构，本文看「为什么」。
> 对应版本：v1.5.2（2026-08）

## 一、产品定位设计

### 1.1 核心等式

```
桌宠 = 常驻动画 + 轻交互 + 人格化输出（台词/AI） + 系统小工具
```

设计取舍围绕一个问题：**一个「没有用处」的程序如何让人不卸载？**
答案是把每一项都做到「不打扰但有事发生」：

| 维度 | 决策 | 反面案例（避免） |
|------|------|-----------------|
| 资源占用 | 单窗口 + 20ms 定时器 + 换行缓存 | 多进程 / 每帧全量计算 |
| 打扰程度 | 台词有冷却、监控默认关、气泡有时长上限 | 高频弹窗 / 常驻监控刷屏 |
| 失败表现 | 错误也要"鱼格化"（气泡台词），但日志留全量 | 静默失败 / 裸 traceback |
| 人格一致性 | 日常台词、回嘴、AI 系统提示词同一人设 | 工具腔报错 |

### 1.2 交互设计三原则

1. **零门槛上手**：双击 bat 即用；首次 AI 对话引导在需要时才出现
   （没 Key 时气泡提示路径，而不是启动就弹表单）
2. **单键多功能靠时序区分**：单击=互动、双击=喂食、按住=拖拽。
   用 280ms 延迟定时器区分单击/双击——代价是单击响应略慢，
   这是桌面宠物的经典取舍
3. **一切都能从右键菜单到达**：包括解除鼠标穿透（穿透后点不到本体，
   必须留托盘入口）——「任何把用户锁死的开关都是 Bug」

### 1.3 功能边界

- 桌宠本体不依赖任何网络服务也能完整运行（AI/天气是增强不是前提）
- 系统监控**默认关闭**（v1.4.0）：宁可用户手动开，不要默认打扰
- AI 回复不硬截断内容（Prompt 引导 25 字是「建议」，代码层面只保留
  120 字防失控上限）——**展示层问题（换行、时长）用展示层解决，
  不动数据**

## 二、工程决策与理由

### 2.1 单文件 → 包结构（何时值得拆）

原版 1043 行单文件。拆分的触发条件不是行数，而是：
- 出现第二类职责（网络层进来了）
- 要写测试（不可导入的 `if __name__` 块无法测）
- 多人协作 / PR 合并冲突

拆分粒度原则：**每个模块能被一句话描述清楚**（"weather.py 就是查天气"），
说不清就继续拆。反例是"utils.py"——那说明还没想清楚。

### 2.2 服务层禁止依赖 Qt（最重要的架构约束）

理由链条：
1. Qt 必须在主线程且需要 QApplication → import 即有环境要求
2. 网络代码最需要测试（超时/重试/解析分支多）→ 必须可脱离 GUI 测试
3. ∴ 网络/解析放 services/，UI 只消费结果

这条约束让 66 个测试里 60+ 个可以纯逻辑跑（毫秒级、无窗口、CI 友好）。

### 2.3 线程模型：消息传递而非锁

后台线程**永远不碰 UI**，只往两个队列塞东西：

```python
self._say_queue.append((text, duration))   # 气泡
self._main_queue.append(callback)          # 主线程回调（弹窗等）
```

为什么不用 Qt 信号槽跨线程（其实也行）：队列把「通信」收敛到
tick 的一个固定位置，读代码时能一眼看到所有跨线程数据流；
且这套模式不依赖 Qt 特性，纯 Python 可测。

**例外**：`DeepSeekClient` 内部有锁——Session 复用必须串行化请求，
这是「资源保护锁」不是「UI 通信锁」，二者要分清。

### 2.4 配置：修改即落盘 + 向前兼容

- 常驻程序死于：崩溃、断电、任务管理器。「退出时保存」= 必丢数据
- 读取时 `DEFAULTS.update(disk)`，未知字段保留——老版本读新配置不崩，
  新版本读老配置补默认
- 数值边界清洗在使用处（`clamp_interval` 钳 5~3600s）而非读取处：
  schema 校验保持宽松，行为校验保持严格

### 2.5 错误处理三级火箭

踩过的坑（v1.1.2 Bug）：错误只弹 2.8 秒气泡且不写日志 → 用户看到
「没反应」，开发者看到 0 字节日志，双向盲区。结论：

| 级别 | 载体 | 内容 | 生命周期 |
|------|------|------|----------|
| 1 提示 | 气泡 | 一句话 + 指路（"右键「测试DS连接」"） | 8 秒（错误类翻倍于普通 2.8s） |
| 2 诊断 | 持久弹窗 | 主动触发的完整结果 + 排查建议列表 | 用户关闭 |
| 3 取证 | logs/pet.log | 全量异常 + API 响应体片段 | 滚动保留 3 份 |

原则：**任何失败路径必须至少落到其中两级**。pythonw 无控制台，
日志文件是唯一取证渠道。

### 2.6 网络Client设计清单（DeepSeek 客户端沉淀）

- Session 复用（省 TLS 握手），按 (key, thinking, proxy) 签名缓存实例
- 异常分类继承（Timeout/Connection/Error），UI 层据类给不同提示
- 仅 429/5xx 重试且指数退避；4xx（Key 错）重试无意义，快速失败
- 流式与阻塞同 API 面积（chat / chat_stream），流式容忍坏行与中途错误
- 响应解析防御：取 `content` 跳过 `reasoning_content`；空回复显式抛错
- 代理可关（`trust_env=False`）：国内环境代理拦截是最常见故障源

### 2.7 测试策略：按 ROI 投入

```
纯逻辑（朝向/时长/码表/payload）→ 全覆盖，毫秒级，最有价值
网络解析（SSE/重试）           → Fake Session 模拟，零真实请求
配置/持久化                     → tmp_path 读写回环 + 损坏注入
GUI                             → 只测踩过坑的点（焦点回归），其余不追
```

教训两条：测试断言别硬编码字面量（默认城市改"深圳"挂了一个测试，
改引用 `DEFAULTS["city"]` 后永不再挂）；GUI 测试要有
`pytest.importorskip` 降级路径，缺依赖不阻塞核心 CI。

### 2.8 命名与文件

- 全英文文件名 + 纯 ASCII 的 bat（原中文 bat 在非 GBK 代码页直接废）
- bat 必须 CRLF（LF 下 label 跳转不可靠）
- 常量即文档：`MONITOR_MIN_INTERVAL_S = 5.0` 替代散落的魔法数字；
  所有可调参数集中 constants.py，改行为不用翻业务代码

## 三、体验细节设计

### 3.1 气泡系统 = 桌宠的"嘴"

- **换行**：按像素宽逐字断行（中文无空格，不能用 word-wrap）
- **时长**：`2.8s + 0.12s/字`，封顶 12s——阅读速度决定停留时间
- **去重**：同句台词不连播；但 `force=True` 供流式刷新绕过
- **思考指示**：`ds_busy` 期间头顶 💭… 动画——等待也要有生命感
- **互斥**：喂食面板弹出前清气泡（同位置会叠）

### 3.2 动画：无帧表的状态机

所有动画 = 归一化时间量 × 三角函数：

```python
jump = -abs(sin(jump_t * π)) * 14 * jump_t   # jump_t: 1→0 衰减
```

好处：零素材依赖（三张静态图走全部动画）、参数即风格（改系数=改性格）、
天然可叠加（呼吸×摇摆×蹦跳相乘不冲突）。

### 3.3 菜单信息架构

高频开关（深度思考/代理/监控）留一级；低频输入（Key/城市/间隔）
收进「设置 ▸」二级。依据：勾选类操作一次点击完成，输入类必然要
弹对话框，多一层菜单不增加成本但显著缩短一级菜单长度。

### 3.4 文案人格化

错误提示也保持人设：「我感觉我的鱼鳍快熟了」（GPU 过热）vs
「GPU temperature exceeds 80°C」。但**诊断弹窗（2 级）回归工具腔**——
排障信息要准确优先于可爱。分层：越接近用户越俏皮，越接近根因越精确。

## 四、规划中功能的设计决策（未实现，定稿于 v1.5.2 文档轮）

### 4.1 多服务商 AI：适配的是「协议」不是「服务商」

市面上 DeepSeek/GLM/Kimi/MiniMax 等绝大多数服务都讲 OpenAI 兼容方言，
真正不同的只有两套协议（OpenAI / Anthropic）。因此：

- **适配层只实现两种协议**，服务商差异收敛为「预设三元组」
  （base_url + 默认模型 + 协议），新增服务商 = 加一行预设，零代码
- 协议差异点集中在三处，各自做成纯函数对：请求体构建
  （Anthropic 的 system 是顶层参数且 max_tokens 必填、思考用
  budget_tokens 而非 reasoning_effort）、响应解析（choices[0].message
  vs content blocks）、流式解析（delta.content vs content_block_delta）
- 客户端骨架（Session 复用/重试/异常分类/历史）与协议无关，不动
- **迁移策略**：旧 `ds_*` 配置键启动时映射为 `ai_*` 等价项并落盘，
  老用户无感升级；DeepSeek 预设就是旧默认值

### 4.2 半透明：降的是「宠物」，不是「窗口」

- 直接 `setWindowOpacity(0.6)` 一步到位，但气泡文字会一起变淡——
  违反「桌宠的嘴必须可读」这条底线
- 正解：**paintEvent 里只对精灵绘制路径包一层 `painter.setOpacity`**，
  气泡层保持 1.0。透明的是身体，嘴永远清晰
- 交互用四档（100/80/60/40）而非滑杆：与「大小」菜单一致，
  档位化选择在右键菜单里比拖滑杆快，且档位值可作配置枚举校验

### 4.3 密钥加密：DPAPI 是桌面应用的正解，但要诚实声明边界

三个候选的取舍：

| 方案 | 结论 | 理由 |
|------|------|------|
| 主密码派生密钥（PBKDF2 + Fernet） | 弃 | 常驻桌宠每次启动要输密码，体验不可接受 |
| 硬编码/混淆密钥对称加密 | 弃 | 伪安全：密钥就在发行包里，给人错误的安全感 |
| **Windows DPAPI** | **采用** | 密钥由 OS 按用户托管，程序零密钥管理；config 被拷到别的机器/账号即无效 |

- 存储格式 `enc:<base64>`，带前缀便于识别与迁移：读到无前缀的明文
  Key（用户手改/旧版残留）→ 加密后立即重写，明文永不落盘过夜
- **必须如实文档化的边界**：DPAPI 防的是配置文件泄露，不防同用户
  进程读取——对开源桌面工具这是合理威胁模型，装作更安全只会误导用户

## 五、可迁移的设计原则速查

1. **依赖单向 + 服务层无 UI 框架** → 可测性的根基
2. **跨线程 = 单向队列**，主循环统一 drain
3. **配置变更即持久化**，schema 宽松 + 行为严格
4. **错误三级可见**：气泡 / 弹窗 / 日志，任何失败至少落两级
5. **重试只对可重试错误**（5xx/限流），其余快速失败
6. **展示问题用展示层解决**（换行/时长），不改数据本身
7. **等待要有反馈**（💭 气泡），沉默 = 假死
8. **任何锁定性开关必须留旁路**（穿透→托盘）
9. **常驻软件默认静音**：监控/通知类功能默认关
10. **测试按 ROI 分层**：纯逻辑全覆盖，GUI 只锁 Bug 回归
